## 3. 通用约定

### 3.1 响应包装

所有 Java 接口返回：

```json
{ "success": true, "message": "ok", "data": {}, "code": null }
```

`success=false` 时 HTTP 状态码与 `code` 对应：`UNAUTHORIZED`(401)、`FORBIDDEN`(403)、`NOT_FOUND`(404)、`VALIDATION_ERROR`(400)、`CONFLICT`(409)、`AI_UNAVAILABLE`(503)、`INTERNAL_ERROR`(500)。前端按 `success` 和 `code` 处理，弹 toast 显示 `message`。

### 3.2 鉴权

- 登录成功后返回 `token`（HMAC-SHA256 签名，含 userId、role、过期时间，有效期 7 天）。
- 除 `POST /api/auth/login`、`POST /api/auth/register`（v1.4）、`GET /api/health` 外，所有接口要求请求头：`Authorization: Bearer <token>`。
- 学生接口仅 STUDENT 可访问，教师接口仅 TEACHER 可访问；越权返回 403 `FORBIDDEN`。
- 令牌无效/过期返回 401，前端清除本地 token 回到登录页。

### 3.3 分页

统一结构：

```json
{ "items": [], "page": 1, "size": 10, "total": 0, "hasNext": false }
```

查询参数 `page` 从 1 开始，`size` 默认 10、上限 100。

| 枚举 | 取值 |

### 3.7 知识覆盖与范围提示（v1.3 五类行为矩阵）

AI 答疑（AI2 `/qa`）与 Java 答疑（S9 `/api/chat`）在五类场景下的返回约定。**硬拦截话术逐字不变（见 3.5）**，`blocked=true` 时 `answer` 必须是该话术原文。v1.3 起教师配置的「暂缓/超纲/禁用」**不再硬拦截**，改为「前置自测 gate → 通过后循序渐进教学」（见 §11.2~§11.4）。

| 场景 | `blocked` | `knowledgeCovered` | `scopeWarning` | `sources` | `gate` | `answer` |
| --- | --- | --- | --- | --- | --- | --- |
| a 硬拦截：课程外数学（线代/矩阵/概率论/物理/复变/数分/离散）、不道德请求（UNETHICAL） | true | false | null | `[]` | null | 3.5 统一话术原文 |
| b 教师配置暂缓/超纲：`disabledTopics`、`effectiveKpIds` 范围外、`boundaryRules` 命中 | false | false | null | `[]` | 非空，`state=QUIZ` | gate 说明话术（见 §11.3）；不给最终答案、不调用 LLM |
| c 非数学但无关：英语/政治/编程/生活天气等 | false | false | 固定范围提醒（说明本系统只辅导高数） | `[]` | null | 给出有帮助的通用回答，并提醒学习范围 |
| d 数学且在范围内，但知识库未命中（检索 `enough=false`） | false | false | null | `[]` | null | 明确「知识库暂无相关内容」+ 建议换问法；不得编造 |
| e 命中：知识库有相关内容 | false | true | null | 非空，元素带 `citation` | null | 结合资料的分层讲解 |

字段定义：

- `knowledgeCovered`（boolean，默认 `true`）：本次回答是否有知识库依据。前端在 `false` 时可提示「知识库未覆盖，以下为通用回答」或如实告知无资料。
- `scopeWarning`（string | null）：范围提醒文案，仅场景 c 非空；前端以提示块展示，不阻断回答。
- `sources` 为空数组时前端不渲染来源列表（场景 a/b/c/d）；场景 e 至少 1 条且带 `citation`。
- `gate`（object | null，v1.3 新增）：仅场景 b 非空，结构见 §11.3。前端渲染「前置自测」卡片，作答后提交 S19（`POST /api/student/gate/check`），通过（≥2/3）返回三步教学与教学答案；未通过可重新提问拿新 gate；`gateId` 过期返回 `state=EXPIRED`。旧客户端忽略未知字段时仍展示 `answer` 说明话术，行为可接受（向后兼容）。
- **硬拦截与 gate 互斥**：场景 a 永不产生 `gate`；场景 b 永不返回 `blocked=true`。
- 上述字段随 `interaction_record.sources`（v1.3 起另含 `gate_json`）一并留痕；旧客户端缺失字段时按 `knowledgeCovered=true`、`scopeWarning=null`、`gate=null` 处理。

## 6. 前端约定

- `src/api.js` 封装 `request(path, {method, body, headers})`：baseURL = `import.meta.env.VITE_API_BASE || 'http://localhost:8080/api'`；自动附加 `Authorization: Bearer <localStorage.ams_token>`；返回 `data`；`success=false` 抛错；401 清 token 跳登录。

- `AI_MODE=auto`（默认）：**`.env` 填了 `DEEPSEEK_API_KEY` 即走真实模型（默认路径，`/health` 显示 `mode=real`）**；未填则自动降级 mock，保证无 key 也能完整演示与验收。
- `AI_MODE=mock` 强制模拟；`AI_MODE=real` 强制真实（无 key 启动即报错）。
- DeepSeek 使用 OpenAI 兼容的 `POST {BASE_URL}/chat/completions`，模型默认 `deepseek-flash`（`deepseek-v4-pro` 可选）。
- 用户把 key 填到 `ai-service/.env` 的 `DEEPSEEK_API_KEY=` 后面即可；`.env.example` 提供模板。
- DeepSeek **不提供**图像输入（vision）能力：图片答疑由 AI17 转发到硅基流动视觉模型（默认 `Qwen/Qwen3-VL-8B-Instruct`）。`VISION_PROVIDER=none` 时图片按钮不可用；未配 `VISION_API_KEY` 时自动回退 `EMBEDDING_API_KEY`。
- 图片隐私与限制：单张 ≤5MB、仅 png/jpeg/webp/gif；图片**不落库、不写日志**，仅在本机压缩后 base64 发往硅基流动做一次识别；提交材料与截图中不得出现真实 key 与含个人信息的图片。

## 11. v1.3 契约增补（2026-11-07，向后兼容）

> 本节是 v1.3 迭代的契约依据（完整背景见 `.tmp/v13-contract.md`；实现状态见 `docs/开发过程/04` §8.3，实测结果已回填 `docs/开发过程/07` §10：2026-11-07 17:35 三端 real 实测 **22/22 PASS**（V-29~V-34、V-29b 全部通过）；本节字段自该轮起按实测生效，后续变更规则见 §11.7）。原则：**只增不改**——新增接口/字段均为可选或向后兼容。

### 11.1 事实前提（2026-11-07 实测）

- DeepSeek 官方 API **不提供 vision（图像输入）能力**：`GET https://api.deepseek.com/models` 仅返回 `deepseek-flash`、`deepseek-v4-pro` 两个 chat 模型。
- 图片识别改走**硅基流动** OpenAI 兼容接口：`POST {VISION_BASE_URL}/chat/completions`，`messages[0].content` 为 `[{type:"text"},{type:"image_url",image_url:{url:"data:image/png;base64,..."}}]`；默认模型 `Qwen/Qwen3-VL-8B-Instruct`（实测约 6 秒/张），可选 `Qwen/Qwen3-VL-32B-Instruct`。
- 可复用 `.env` 已有的 `EMBEDDING_API_KEY`（同一硅基流动账号）：`VISION_API_KEY` 留空时自动回退，无需重复配置。

### 11.2 教师配置语义变更（v1.3）

`ai-service/app/rules.py` 原 `check_scope()` 把「教师配置命中」与「课程外数学/不当请求」一并判为硬拦截。v1.3 拆成两条判定：

| 函数 | 匹配范围 | 结果 |
| --- | --- | --- |
| `hard_scope_hit(message)`（保持原硬拦截语义，旧测试继续使用） | `HARD_SCOPE_KEYWORDS`（线代/矩阵/概率论/物理/复变/数分/离散）与不当请求（UNETHICAL） | `blocked=true` + 3.5 统一话术（`answer` 逐字），**不产生 gate** |
| `teacher_scope_hit(message, config) -> (topic, reason)` | `teacherConfig.disabledTopics`、`effectiveKpIds` 范围外的知识点、`boundaryRules` | 命中则返回 gate（§11.3），`blocked=false`，不调用 LLM |

判定顺序（AI2 `/qa` 与 mock 一致）：① `hard_scope_hit` → 硬拦截；② `teacher_scope_hit` → 若同一 `(conversationId, topic)` 已通过前置测试（TTL 2 小时）→ 放行走正常检索答疑；否则返回 gate quiz；③ 正常答疑流程（检索 → 生成 → 引用）。

### 11.3 AI2 `/qa` 响应新增 `gate` 字段

教师配置暂缓/超纲命中时，`gate` 非空、`state=QUIZ`，同时 `blocked=false`、`sources=[]`、`knowledgeCovered=false`、`action={type:"GATE",label:"前置自测",params:null}`，`answer` 为说明话术（不调用 LLM）：

```json
{"answer":"这道题涉及「级数」，属于教师配置的暂缓内容。我先用 3 道前置小题确认基础；通过后我会用三步带你学会它，不会直接给作业答案。",
 "sources":[], "blocked":false, "blockReason":null, "knowledgeCovered":false, "scopeWarning":null,
 "action":{"type":"GATE","label":"前置自测","params":null},
 "gate":{"gateId":"g-8f3c2a1b", "topic":"级数", "state":"QUIZ",
   "reason":"该问题涉及教师已禁用的内容「级数」", "message":"通过后我会用三步带你学会「级数」。",
   "prerequisites":[{"kpId":"kp028","kpName":"原函数与不定积分的概念","citation":"《高等数学教材讲义》第5章·第1节"}],
   "questions":[{"questionId":"gq1","index":1,"kpId":"kp028","kpName":"原函数与不定积分的概念","difficulty":1,
     "stem":"下列函数中，哪一个不是 f(x)=2x 的原函数？","options":[{"key":"A","text":"x^2"},{"key":"B","text":"x^2+1"},{"key":"C","text":"x^2-3"},{"key":"D","text":"2x^2"}]}],
   "score":null, "total":3},
 "mode":"real", "model":"deepseek-flash", "modelSource":"system", "conversationId":"12"}
```

`gate` 对象字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `gateId` | string | `g-` + 8 位十六进制；每次提问重新生成 |
| `topic` | string | 命中的主题/知识点名，如「级数」 |
| `state` | enum | `/qa` 只返回 `QUIZ`；判分状态机见 §11.4 |
| `reason` | string | 触发原因（禁用话题 / 范围外 / 边界规则） |
| `message` | string | 教学承诺（通过后三步教学） |
| `prerequisites` | array | 前置知识点 `[{kpId,kpName,citation}]`（0~3 项） |
| `questions` | array | 固定 **3** 道单选题 `[{questionId,index,kpId,kpName,difficulty,stem,options:[{key,text}]}]` |
| `score` | int \| null | 未提交为 `null`（`/qa` 恒为 null） |
| `total` | int | 题数，固定 3 |

gate 出题规则：

- 题源为 AI 服务内置题库（`ai-service/app/builtin_questions.py`，36 题 / 30 题带 `options` 与 `answerKey`，覆盖 22 个知识点）；取 `options` 与 `answerKey` 非空、难度 ≤2 的题，优先选用主题所在章节**之前**的 2~3 个前置知识点（同章前一节亦可），排除主题自身知识点。
- **正确答案只存服务端** `GateStore`（按 `gateId`，TTL 2 小时），任何接口都不返回 `answerKey`。
- `VISION`/`gate` 均支持 mock 模式离线出题，不依赖外部服务。
- 同一 `gateId` 可重复提交（重测需重新提问拿新 gate）。

判定与状态机：

- **通过线 2/3**（`score >= 2` 即 `passed=true`）。
- `PASSED`：生成三步教学（real 用 DeepSeek 生成，要求「不给作业/考试最终答案、引用 `citation`」；生成失败降级到 mock 模板，模板必须含「第 1 步」「第 2 步」「第 3 步」）；`sources` 非空、`knowledgeCovered=true`。
- `FAILED`：**不调用 LLM**，`answer` 为空或简短鼓励、`sources=[]`、`knowledgeCovered=false`；前端提示可重新测试。
- `EXPIRED`：`gateId` 不存在或超过 TTL 2 小时，提示「前置测试已过期，请重新提问。」。
- 通过后 `(conversationId, topic)` 记入 passed 集合（TTL 2 小时）：同一会话再问该主题直接正常答疑、不再返回 gate。
- 状态机：`QUIZ` →（提交判分）→ `PASSED` / `FAILED`；超过 TTL → `EXPIRED`（不可再提交）。

## 12. v1.4 契约增补（2026-11-08，向后兼容）

> 本节是 v1.4 迭代的契约依据：新增 A19「学生自助注册」与 A20「教师重置学生密码」，并明确默认班级归属与掌握度初始化规则。原则：**只增不改**——既有接口字段与语义不变（A1/A2/A4/A5、S9 等全部按原契约）。实现状态：**契约已冻结；Java 接口已实现，验收 C-22/C-23 已于 2026-11-08 09:57 三端 real 实测通过（24/24 PASS，见 `docs/开发过程/07` §11）**（前端注册 tab 与重置弹窗已完成联调，截图 S-17/S-18）。

### 12.1 背景与目标

- 现状（v1.3）：账号只来自 `DemoDataSeeder`（teacher1/2、student1~5），学生无法自助注册；学生忘记密码时无重置途径。
- v1.4 目标：
  1. 登录页提供「注册」入口：学生填 `username/password/displayName`（`email` 可选）即可注册，**注册即登录**（响应与 A1 同构，前端拿到 `token` 直接进入学生端，无需二次登录）；
  2. 教师在教师端学生列表为学生**重置密码**（无需知道旧密码）。
- 账号边界：A19 只创建 `role=STUDENT`；教师账号不开放自助注册（仍由种子数据/管理员维护）。
- 新学生归属：统一落到配置 `app.default-class-id`（默认 `C-GS-01`「考研高数强化班」）；注册请求**不带** `classId`，前端不展示班级选择。

### 12.2 初始化规则（注册成功后必做）

| 项 | 规则 |
| --- | --- |
| `user_info` | 新增 1 条：`username`/`password_hash`（PBKDF2 散列）/`display_name`/`role=STUDENT`/`class_id=app.default-class-id`/`email`（可空），`created_at=now` |
| `student_kp_mastery` | 立即写入 **67 条**（对应 `knowledge_point` 全部 67 个知识点）：`mastery=0.00`、`attempts=0`、`correct_count=0`、状态按 [05-数据模型](05-数据模型与初始化数据.md) 的阈值规则初始化为「待学习」 |
| 事务 | 「建账号 + 写 67 条掌握度」在**同一事务**；任一失败整体回滚，不得留半初始化账号 |
| 幂等/并发 | `user_info.username` 唯一约束兜底：并发注册同名时后到者返回 409，不产生重复账号 |
| 默认班级缺失 | `app.default-class-id` 指向的班级不存在 → 500 `INTERNAL_ERROR`（部署配置错误，启动日志 WARN）；不得静默落到其他班级 |

> 为什么必须初始化 67 条：学生端首页/诊断/练习/计划均以 `student_kp_mastery` 聚合，缺行会出现空数据或统计偏差；v1.0 起种子学生即按此规则初始化，新注册学生保持一致。

1. 密码更新只影响 **A1 登录校验**：旧密码下一次登录即失败（401/400）；
2. 已签发的 token **不吊销**：§3.2 的 token 是无状态 HMAC（含 userId/role/过期，7 天），服务端不维护黑名单，因此重置前签发的 token 在到期前仍可用；前端在「修改/被重置密码」后引导重新登录属 UI 行为，不构成服务端吊销；
3. 如需强制下线，属 P2 增强（`user_info.token_version` 或黑名单），本版契约不引入。

### 12.4 鉴权与安全边界（v1.4）

1. **免鉴权清单扩展**：自 v1.4 起 `POST /api/auth/register` 与 `POST /api/auth/login`、`GET /api/health` 同为公开接口（§3.2 口径相应扩展）；其余接口仍需 `Authorization: Bearer <token>`。
2. **密码存储**：沿用 `security/PasswordHasher`（`PBKDF2WithHmacSHA256`，120000 次迭代、16 字节随机盐、256 位，格式 `iterations:saltBase64:hashBase64`）；注册与重置均走同一散列入口，任何接口/日志/异常信息**不得**出现明文密码或散列值。
3. **A20 越权校验顺序**：先校验 `studentId` 存在且角色为 STUDENT（404），再校验 `student.classId == 当前教师 classId`（403），顺序不可颠倒（避免用 404/403 差异枚举他班学生）。
4. **注册接口公开的已知取舍**：本版不限流、不校验邮箱真实性、重复用户名明确 409（便于演示）。生产化建议（P2）：频控/验证码、邮箱验证、统一失败文案防用户名枚举。
5. **数据最小化**：注册只收集 `username/password/displayName/email`；`phone/targetSchool/examYear` 留空，由学生在 A5 个人信息页自行补全。

### 12.8 v1.4.1 内部实现说明（gate 持久化，不改对外契约）

v1.4.1 只改 AI 服务的**内部存储**，`/qa/*` 的请求/响应字段、错误码、状态机均不变，故本节不改上面任何接口定义，仅说明实现边界（验收见 [07-测试与验收记录](07-测试与验收记录.md) §12，设计与 schema 见 [10-技术栈与架构说明](10-技术栈与架构说明.md) §4.12）。

1. **存储位置**：前置自测（gate）与其「已通过」标记由进程内存改为本地 SQLite，默认库文件 `ai-service/data/gate.db`（目录不存在自动创建）；可用环境变量 `AI_GATE_DB` 覆盖路径。两表：`gates`（gate 全量定义与判分状态）与 `gate_passed`（主键 `(conversation_id, topic)`，记录通过到期时间）。
2. **有效期不变**：仍是 2 小时（`GATE_TTL_SECONDS = 7200`，从创建算起），读写时顺带清理过期行；对外提示与错误码不变。
3. **重启语义**：未过期的 gate 在服务重启后仍可提交并判分（`progress` 可继续），因此「gateId 仅在 AI 进程内、重启即失效」的旧说法作废；同 `conversationId` + 同 topic 已通过者，重启后也不再重复出题（直接进入正常答疑）。
4. **过期语义**：超过 TTL 的 gate 读取视为不存在，按新话题重新出题；过期的通过标记同样失效（会重新自测）。
5. **降级**：库目录不可创建或 SQLite 报错时自动回退 `:memory:`（仅记日志），此时行为退回 v1.3（重启不保留），对外接口不受影响。
6. **安全边界**：gate 的正确答案**仍然只存服务端**、绝不下发；客户端只能拿到题目与选项。`score`/`passed` 由服务端判分写入。
7. **运维**：删除 `ai-service/data/gate.db`（或清空两表）即重置全部 gate 状态，无需重启也能生效于后续请求。
8. **未变更项**：不新增接口、不新增字段、不改错误码；v1.4 的 A19/A20 与 24 项验收口径不受影响。
