## 1. 目标与交付边界

把扣子中跑通的智能体原型，落地为可运行、可演示、可验收的全栈系统：

- **学生端**：登录、首页概览、答疑辅导（引导式）、知识诊断、学习计划、分层练习、学习记录、错题复盘、个人信息；
- **教师端**：学情总览、班级配置（回答模式/难度/知识范围/边界/知识库权限/禁用话题，修改立即生效并留痕）、班级学情分析、知识库管理、学生记录；
- **AI 服务**：RAG 检索（v1.1：LangChain `InMemoryVectorStore` + 本地 Embeddings）+ W0~W4 五类工作流（意图识别、答疑、诊断、计划练习、配置抽取与班级分析），real 为默认、mock 为无 key 降级；
- **数据**：PRD 7 张核心表 + 3 张辅助表（`class_info`、`config_change_log`、v1.2 起的 `conversation`），实库共 10 张表，空库自动初始化演示数据；
- **工程**：一键启动/停止脚本、环境检查、H2 重置、三端验收脚本、完整文档与提交材料。

**v1.1 增补范围**（2026-11-07 起）：把「轻量 TF 检索」升级为 LangChain `InMemoryVectorStore` + 本地字符 n-gram 哈希 Embeddings；`SourceRef` 增加 `chapter/section/citation`；答疑增加 `knowledgeCovered/scopeWarning` 与四类场景行为矩阵；健康检查暴露向量库指标；默认运行模式明确为 real（`.env` 有 key）、mock 为降级。

不在本期范围（P2，写入 §12 后续迭代）：图片 OCR 识题、流式输出、多班级/多课程扩展、移动端适配。

## 2. 总体架构

```text
浏览器（Vue3 + Vite，:5173）
   │  fetch  http://localhost:8080/api/**   Authorization: Bearer <token>
   ▼
business-service（Spring Boot 3.4.2 + JPA + H2 文件库，:8080）
   │  · 登录鉴权（HMAC-SHA256 token）、角色/班级权限、统一响应与异常
   │  · 7 张业务表 + 配置留痕；教师配置实时读取
   │  · 掌握度结算、错题沉淀、班级聚合统计、报告落库
   │  · JDK HttpClient 调 AI 服务（超时/降级）
   ▼
ai-service（FastAPI + uvicorn，:8000）
   │  · W0 意图识别 → W1 答疑 / W2 诊断 / W3 计划练习 / W4 配置抽取与班级分析
   │  · RAG v1.1：LangChain InMemoryVectorStore + 本地 n-gram 哈希 Embeddings；5 类知识库切块、向量 top-k、阈值判定、教师范围过滤
   │  · AI_MODE=auto/mock/real：.env 有 key 默认 real，无 key 自动降级 mock（验收/离线演示仍可全程跑通）
   ▼
DeepSeek（OpenAI 兼容 POST /chat/completions，模型 `deepseek-flash`）
```

### 2.1 三服务职责与边界

| 工程 | 技术栈 | 职责 | 明确不做 |
| --- | --- | --- | --- |
| `frontend` | Vue3.5 + Vite6 + marked + KaTeX | 页面渲染、表单校验、loading/toast/空态、token 管理、公式渲染 | 不直连 AI 服务；不写业务规则 |
| `business-service` | Java 17 + Spring Boot 3.4.2 + Spring Data JPA + H2 | 鉴权与权限、业务编排、数据落库、掌握度/统计、报告与错题、调用 AI、统一响应 | 不写提示词、不做检索、不直接访问 DeepSeek |
| `ai-service` | Python 3.12 + FastAPI + httpx | 意图识别、RAG 检索、五类工作流生成、mock/real 切换、知识库索引管理 | 不连业务库、不鉴权、不落业务数据（诊断报告由 Java 落库） |

**数据流约束**：Java 是唯一业务数据入口；AI 服务只接收上下文、返回结构化结果。诊断/计划/练习的报告内容由 Java 写入 `report` 表，保证教师端统计与学生端记录同源一致（验收 8.1-6）。

### 2.2 关键设计决策

| 决策 | 理由 |
| --- | --- |
| 不新增 Java 第三方依赖 | 课堂/离线环境 Maven 仓库可能缺包；token 用 JDK HMAC-SHA256，密码 PBKDF2，HTTP 用 JDK `HttpClient` |
| H2 文件库 + `ddl-auto=update` + 幂等种子数据 | 不装 MySQL，换电脑可复现；`AUTO_SERVER=TRUE` 允许控制台与程序同时连接 |
| 诊断会话/练习批次/计划/班级分析统一存 `report` | 诊断/练习/计划/班级分析在 7 表约束内不新增会话表，`sessionId=reportId`、`batchId="PB"+report.id`；v1.2 仅新增 `conversation` 表专供答疑多轮上下文，上述四类仍复用 `report` |
| RAG 用 LangChain 向量检索（v1.1） | 知识库规模小（5 类文档、**当前实测 60 块**），`InMemoryVectorStore` + 本地 n-gram 哈希 Embeddings 可离线、零外部调用、启动快；`/retrieve` 契约不变，`retrieval.py` 保留作对照与回退 |
| real 默认、mock 降级 | `AI_MODE=auto`（默认）：`.env` 有 `DEEPSEEK_API_KEY` 即走 DeepSeek（默认路径 `mode=real`）；无 key 自动降级 mock，保证验收与离线演示仍可全流程跑通，无需改代码 |
| 前端不引入 vue-router | 保持现有左侧栏单文件多页结构，减少依赖与联调风险；状态存 `localStorage` |
| 配置实时生效 | 每次学生请求 Java 现读 `class_teacher_config` 并注入 AI，不缓存旧配置（验收 8.2-3） |

## 5. RAG 与知识库方案

### 5.1 知识库目录（`ai-service/knowledge/`）

| 目录 | KB | 内容 | 默认可见 |
| --- | --- | --- | --- |
| `kb1_outline/` | KB1 | 高等数学课程大纲（章节/知识点/要求） | 全局（教师可停用） |
| `kb2_textbook/` | KB2 | 教材讲义：定义、定理、例题、常见错误 | 全局 |
| `kb3_questions/` | KB3 | 分层题库：A/B/C 难度、题型、解析 | 全局 |
| `kb4_teacher/` | KB4 | 教师授权资料（示例讲义 + 上传件） | 默认关闭，教师开启后本班可用 |
| `kb5_graph/` | KB5 | 知识图谱：前置依赖关系（仅后台计算，不检索返回） | 不暴露 |

`knowledge/knowledge_points.json` 提供 67 个知识点的结构化元数据（kpId、名称、章节、难度、学时、目标、要点），供初始化与检索关联。

### 5.2 索引与检索（v1.1 LangChain 向量库；v1.2 混合检索与去重）

1. **两级切块**：启动时加载 `knowledge/**/*.md`，先按标题层级 + 段落切成**知识块**（约 600~800 字）：v1.1 实测 **5 份文档、60 个知识块**（KB1=11、KB2=23、KB3=12、KB4=5、KB5=9）；再用 `langchain-text-splitters` 的 `RecursiveCharacterTextSplitter(chunk_size=420, chunk_overlap=60)` 切成**检索单元**：v1.1 实测 **135 个**（429~609 字）；**v1.2 起二级切分先按行首 `kpNNN` 把知识块对齐知识点再切分**，实测 **276 个**（135→276）。metadata 记录 `documentId / kb / title / chapter / section / kpId / citation / unitId`。**60 与 276 的差异属两级切分的预期结果**（v1.1 为 135），`/health` 的 `knowledge_chunks=60` 与 `vector_count=276` 各自对应，验收时要求说明而非要求相等（见 `docs/开发过程/07` §8 V-02）。
2. **向量化**：自定义本地 `Embeddings`（字符 n-gram 哈希到固定维度、L2 归一化），零外部调用、可离线、启动快；不依赖在线 embedding API，答辩环境无网也能跑。
3. **索引**：LangChain `InMemoryVectorStore`（`langchain-core 1.7.6`）；启动时重建，知识库上传/启停/删除与 `POST /ai/knowledge/rebuild` 后自动重建；索引可持久化到 `ai-service/data/vector_index.json`，重启可恢复。
4. **检索**：查询改写（W1-A 规则：补全术语/定理全称）→ `similarity_search_with_score(query, k=8)` → 分数归一化与阈值判定（低于当前 embedding 方案阈值视为「知识库无相关内容」：`local` 0.15 / `openai` 0.40）→ 过滤（KB 权限、班级授权、教师 `effectiveKpIds`、禁用话题）→ 取 Top-K。
5. **来源**：`SourceRef{documentId,kb,title,chapter,section,citation,excerpt,score,kpId,chunkId}`；`citation` 由 `knowledge_points.json` 的 `chapter` 推导，形如 `《高等数学教材讲义》第2章·第5节 洛必达法则`，前端来源卡片优先展示 citation。
6. **对照与回退**：保留 `retrieval.py`（字符 bigram + TF-IDF）作对照实现与开关；`/retrieve` 契约不变，Java 与前端无感。

**v1.2 增补（检索质量，详见 [01 §10](01-接口约定.md)）**：

7. **查询归一化与扩展**：`query.py` 先做全角/半角、空白、符号归一化，再按同义词表扩展（如「分部积分」→「分部积分法/分部积分公式」）；`QUERY_EXPANSION=auto` 且 real 模式时，用 DeepSeek 把口语化问题改写成含概念词的检索语句，失败静默回退规则扩展。
8. **混合检索**：向量相似度 + 关键词命中加权合并后用统一阈值判定 `enough`；解决「求 ∫2xe^xdx」这类公式/术语提问向量召回不足的问题（验收用例见 01 §10.2）。
9. **来源去重**：`sources` 按 `chunkId` 去重，同一检索单元重复命中只保留最高分一条；前端来源卡片标题显示「知识库来源（N 段）」并按片段去重。
10. **可插拔 Embedding（B 轨）**：`embeddings.py` 按 `EMBEDDING_PROVIDER=local|openai` 选择实现；`openai` 走 OpenAI 兼容 `/embeddings`（`EMBEDDING_BASE_URL/API_KEY/MODEL`），缺 key 或调用异常自动回退 `local`，`/health` 上报实际生效的 `embedding_provider/embedding_model/embedding_dim`。默认 `local`。**阈值随方案区分**（2026-11-07 校准）：`local` 用 `RETRIEVAL_MIN_SCORE`（0.15），`openai` 用 `EMBEDDING_MIN_SCORE`（0.40，语义向量无关问题基线 0.28~0.39），`/retrieve` 的 `minScore` 不传时取方案阈值。
11. **答案文本清理**：后处理移除「片段 N」「chunk N」「kpNNN」等内部编号，改为引用 `citation` 或「知识库相关章节」；避免学生看到内部实现细节（01 §10.3）。

## 6. mock / real 双模式

配置文件：`ai-service/.env`（模板 `.env.example`，**不提交真实 key**）：

```ini
AI_MODE=auto
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
LLM_TIMEOUT_SECONDS=90
# v1.2 检索增强（均可留空，留空走默认）
EMBEDDING_PROVIDER=local        # local | openai（openai 需配下方三项，缺 key 自动回退 local）
EMBEDDING_BASE_URL=
EMBEDDING_API_KEY=
EMBEDDING_MODEL=
EMBEDDING_MIN_SCORE=0.40        # 仅 provider=openai 生效的覆盖阈值（语义向量无关问题 0.28~0.39）
RETRIEVAL_MIN_SCORE=0.15        # 仅 provider=local 生效的覆盖阈值
QUERY_EXPANSION=auto            # auto | off
# v1.3 图片转文字（视觉模型，硅基流动 OpenAI 兼容；DeepSeek 无图像输入）
VISION_PROVIDER=auto            # auto | siliconflow | none（none 时 AI17 返回 ok=false）
VISION_BASE_URL=https://api.siliconflow.cn/v1
VISION_API_KEY=                 # 留空则回退复用 EMBEDDING_API_KEY
VISION_MODEL=Qwen/Qwen3-VL-8B-Instruct
VISION_TIMEOUT_SECONDS=60
```

| 模式 | 行为 | 用途 |
| --- | --- | --- |
| `auto`（默认，推荐） | **有 key → real（默认路径）；无 key → mock（自动降级）** | 正常演示走 real；换电脑/无 key 环境仍可全流程跑通 |
| `real` | `httpx` 调 DeepSeek `/chat/completions`，`temperature=0.3`，超时 90s；失败自动降级并标 `mode=fallback` | 真实效果演示与答辩效果图（默认模式） |
| `mock` | 确定性模板生成：按意图与检索结果拼装答案/题目/报告，规则校验与真实模式一致 | 无 key / 无网 / 自动化验收（`scripts/acceptance_check.py`） |

> 默认基线：`ai-service/.env` 配置 `DEEPSEEK_API_KEY` 后，`AI_MODE=auto` 即走 `real`，`/health` 显示 `mode=real`；删除 key 或置空则自动降级 `mock`，无需改代码。仓库只提交 `.env.example`，**不得提交真实 key**。

**降级**：真实模型超时/报错/429 时，返回 mock 结果并在响应中标注降级；Java 记录日志，不使接口 500（验收 8.3-2）。

**模型名口径（v1.2）**：以 `ai-service/.env` 的 `DEEPSEEK_MODEL` 为准（本机实测 `deepseek-flash`，DeepSeek 当前可用模型为 `deepseek-flash`/`deepseek-v4-pro`）；`.env.example`、代码缺省值（2026-11-07 已统一）与 `/health` 实测均为 `deepseek-flash`，部署后仍以 `/health` 显示的 `model` 为准。

**用户自带 Key（v1.2）**：学生/教师可在「个人信息 → AI 模型设置」填自己的 `API Key/Base URL/模型`；Java 用 AES/GCM 加密存库（`CryptoUtil`，密钥 `app.crypto.secret`），接口只回掩码；`/api/chat` 解密后随 `llm` 传给 AI，AI 响应 `modelSource=user`（失败降级系统 Key → `system`，再失败 → `mock`）。**Key 不写日志、不回显、不落明文**。

**提示词文件**：`ai-service/app/prompts.py`（W0 意图、W1-A 改写、W1-B 答疑、W2 诊断、W3 计划练习、W4-A 配置抽取、W4-B 班级分析，以模块常量组织），迁移自扣子文档并补充输出 JSON 约束；映射见 [08-扣子到代码映射与提示词](08-扣子到代码映射与提示词.md)。

**边界拦截（v1.3 起分两级，契约 01 §11.10）**：① **硬拦截**——课程外数学（线代/矩阵/概率/物理/复变/数分/离散等）与不当请求（`HARD_SCOPE_KEYWORDS`/`UNETHICAL`），返回 `blocked=true`、`modelSource=none` 与统一话术「该内容超出当前教学范围，暂时无法解答。」（01 §3.5），Java 侧另按 `maxDifficulty` 预检；② **教师暂缓内容**（`disabledTopics` / 超出 `effectiveKpIds` 范围 / `boundaryRules`）——**不再直接拦截**，改由 AI 先出 3 道前置自测题（`gate.state=QUIZ`、3 题单选、答案只存 AI `GateStore`、`blocked=false`、`sources=[]`、不调 LLM），通过线 **2/3**，通过后（同 `conversationId`+topic，TTL 2h）走正常答疑并用「第 1 步/第 2 步/第 3 步」循序渐进教学（不给作业最终答案）。

**引导式校验**：`answerMode=GUIDED` 或作业类提问时，提示词禁止给最终答案，输出后再做正则检测（如「最终答案/答案为/综上所述」），命中则替换为思路提示。
