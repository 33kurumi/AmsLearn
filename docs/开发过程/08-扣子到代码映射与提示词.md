## 2. W0 主调度（意图识别）

- **扣子做法**：开始节点取 `user_id/user_message/image_url` → 查 `user_profile` → 意图 LLM 输出 `qa/diagnose/plan_practice/config_set/class_analysis/unknown` → 多路分支调子工作流。
- **代码做法**：身份校验由 Java 的 `AuthInterceptor` + `UserContext` 完成（等价扣子「查询 user_profile」）；意图由 AI3 `/ai/intent` 识别（规则优先、LLM 兜底），Java 的答疑服务据此决定走答疑/诊断/计划分支，未知意图返回统一引导话术。
- **接口**：请求 `{message, role}` → 响应 `{intent, confidence}`；intent 枚举与 01 契约一致（qa/diagnose/plan/practice/unknown）。
- **关键规则**：只输出标签不答题；学生标签限 qa/diagnose/practice，教师限 config/analysis；多意图优先级 诊断 > 计划练习 > 答疑；unknown 返回引导文案。
- **兜底**：AI 服务不可用时 Java 按默认意图 `qa` 处理并提示，不让请求失败。

## 3. W1 学生答疑（核心链路）

链路：`S9 /api/chat` → Java 读取班级配置 + 学生掌握度 + 近期记录 → `AI2 /ai/qa` →（AI 内部：W1-A 改写 → AI4 `/retrieve` 检索 → W1-B 生成）→ Java 写入 `interaction_record` → 返回 `reply/sources/blocked`。

提示词变量与代码字段对照：

| 扣子变量 | 代码来源 |
| --- | --- |
| `{{teacher_config}}` | Java 每次请求实时读 `class_teacher_config`（不缓存 → 满足 8.2-3 立即生效），随 `/ai/qa` 请求体的 `config` 传入 |
| `{{mastery_data}}` | `student_kp_mastery` 中该生薄弱/已学记录，取薄弱优先前 N 条 |
| `{{kb_retrieve}}` | AI 服务本地知识库检索结果（KB1~KB4），带文件名/片段/相似度 |
| `{{user_message}}` | 请求体 `message`；**v1.3 起** 图片先经 S18/AI17 转成文字回填输入框，再由用户确认后作为 `message` 发送，因此答疑提示词只需文字 |

关键规则（必须在代码中体现，验收 8.1-1/8.1-2/8.2-1/8.2-2）：

1. 知识库内容为权威源，无相关内容时固定话术「知识库暂无该知识点资料」且不编造；v1.1 对应返回 `knowledgeCovered=false`、`sources=[]`；
2. 边界分两级（**v1.3 语义变化**）：① **硬拦截**只对课程外数学（线代/矩阵/概率论/物理/复变/数分/离散）与不当请求，返回契约固定话术「该内容超出当前教学范围，暂时无法解答。」（`blocked=true`、`knowledgeCovered=false`、`sources=[]`、`modelSource=none`）；② 教师配置的暂缓/超纲内容（`disabledTopics`/`effectiveKpIds` 之外/`boundaryRules`）**不再直接拦截**，改返回 3 题前置自测 `gate`（`blocked=false`、`sources=[]`、不调用 LLM），通过后按三步教学；
3. 作业/练习场景只给思路与追问，不输出最终答案与结果；概念讲解可完整展开；
4. 回答分层（定义/条件/步骤/易错点）、公式用 `$$...$$`/`$...$` 包裹，前端 KaTeX 渲染；
5. 个性化：薄弱知识点重点展开，已掌握简要带过；
6. 每次交互写 `interaction_record`（学生提问、AI 回答、sources、intent、时间）。

**v1.3 五类场景（与 01 §3.7、docs/开发过程/04 §6.1、10 §4.1 一致）**：

| 场景 | blocked | knowledgeCovered | scopeWarning | gate | sources |
| --- | --- | --- | --- | --- | --- |
| a 硬拦截（课程外数学：线代/矩阵/概率/物理/复变/数分/离散；不当请求） | true | false | null | null | [] |
| b 教师配置暂缓/超纲（`disabledTopics`/范围外/`boundaryRules`） | false | false | null | `state=QUIZ`（3 题，答案只存服务端） | [] |
| c 非数学无关（英语/政治/编程/生活） | false | false | 固定范围提醒 | null | [] |
| d 数学在范围内但知识库未命中 | false | false | null | null | [] |
| e 命中知识库 | false | true | null | null | 非空，带 citation |

> 场景 b 的 gate 通过（≥2/3）后，同一会话再问同主题按场景 e 正常答疑（TTL 2 小时）。

来源引用（v1.1）：`SourceRef` 增加 `chapter/section/citation`，`citation` 形如《高等数学教材讲义》第2章·第5节 洛必达法则，由 `knowledge_points.json` 的章节元数据推导。

### 3.1 v1.2：检索改写与「扣子 W1-A」的对应

| 扣子 W1-A 步骤 | v1.2 代码落点 | 说明 |
| --- | --- | --- |
| 用户问题 → 查询改写 | `ai-service/app/query.py` 的归一化（全半角/空白/数学符号）+ 规则同义扩展（「分部积分」「求导」「洛必达」等） | 默认总开，`QUERY_EXPANSION=auto` 时 real 模式再用 DeepSeek 改写并抽概念词 |
| 改写结果 → 向量检索 | `retrieval.py`/`knowledge.py`：LangChain `InMemoryVectorStore` 相似度 + 关键词命中，混合打分后取 Top-K | 解决「求 ∫2xe^xdx」这类含公式/符号的问法检索不到「分部积分法」的问题（V-10） |
| 检索结果 → 送进 W1-B 提示词 | `prompts.py` 的 `{{kb_retrieve}}` 变量改为按 `citation`（章节）拼装 | 每段带 `chapter/section/citation`，来源按 `chunkId` 去重（同检索单元保留最高分） |
| 生成后 → 后处理 | `service.py`/`rules.py`：把「片段 N」「chunk N」「kpNNN」替换为 `citation` 或「知识库相关章节」 | 硬性要求见契约 01 §10.3；未覆盖时固定「知识库暂无相关内容」+「换一种问法」 |
| 多轮上下文 | `/ai/qa` 请求的 `history`（Java 传最近 6 条、AI 再截断 8 条 / 4000 字符）拼进 W1-B 提示词 | mock 模式也会体现「结合上文」；不影响单轮调用（不传即单轮） |

### 3.2 v1.2：用户 Key 与模型来源在提示词链路中的位置

- Java 在 `/api/chat` 里解密用户 Key（AES/GCM），以 `llm{apiKey,baseUrl,model}` 随 `/ai/qa` 一次性传入；AI 侧**只用本次请求**，不落盘、不写日志、不回显；
- `/ai/qa` 响应新增 `model`、`modelSource`（`system`/`user`/`mock`），Java 原样返回给前端，顶栏徽标与回答底部据此显示「real · 模型 · 系统 Key / 我的 Key / mock」；
- 用户 Key 失效时 AI 降级系统 Key（`modelSource=system`），系统 Key 也失败再降级 mock（`modelSource=mock`），提示词规则不变，验收话术不受影响。


## 4. W2 知识诊断

- **出题**：`S10 /api/diagnose/start` → AI5 `/ai/diagnose/questions`，入参含 `classId/count/difficulty/scope`；返回 `sessionId` + 5 道题。题目来源：`knowledge/kb3_questions.md` 题库 + `knowledge_points.json`（67 个知识点），按薄弱点与班级难度上限筛选；**学生侧返回不含 `answerKey/analysis`**。
- **批改**：`S11 /api/diagnose/{sessionId}/submit` → AI6 `/ai/diagnose/grade`，逐题判分并归因：概念混淆 / 计算失误 / 审题偏差 / 方法不当（枚举见 01）。
- **报告与掌握度**：Java 生成 `report`（reportType=DIAGNOSIS，sessionId=reportId）并更新 `student_kp_mastery`（答对 +0.05、答错 -0.10，clamp 0~1；规则详见 docs/开发过程/05 §5）与 `wrong_question`；返回 score/level/weakPoints/suggestions/masteryChanges。
- 诊断会话状态：`report.sessionId` 对应 `/api/diagnose/start` 返回的 sessionId，报告状态 IN PROGRESS→COMPLETED，提交后不可重复提交（冲突返回 `CONFLICT`）。

## 5. W3 学习计划 + 分层练习

- **分层练习**：`S12 /api/practice/generate` → AI7；按 `layer`（A 基础/B 提升/C 拓展）出题，难度映射 A=1~2、B=2~3、C=3~4，并 clamp 到教师 `maxDifficulty`；返回 `batchId="PB"+report.id`；题干不含答案。
- **思路提示**：`S13 /api/practice/hint` → AI8，只给下一步思路/追问，不给最终结果（8.1-2）。
- **学习计划**：`S14 /api/plans/generate` → AI9，返回固定结构 `days[{day,study,practice,review,goal}]`；Java 落库 `report`（reportType=PLAN）；`S15~S17` 学生端查看/更新进度。
- 关键规则：计划可落地（按天、按知识点）、练习命中薄弱点、难度不超上限、不超知识范围。

## 6. W4 教师配置与班级学情

- **W4-A 配置抽取**：`T5 /api/teacher/config/extract` → AI11 `/ai/config/extract`，把教师自然语言转结构化字段：`answerMode`（GUIDED/DIRECT/MIXED）、`maxDifficulty`（1~4）、`knowledgeScope`、`forbiddenTopics`、`kbAccess`；抽取结果**回填前端表单**，教师确认后 `PUT /api/teacher/config` 保存，并写 `config_change_log`（变更前后对比）。
- **W4-B 班级分析**：`T6 /api/teacher/analysis` → AI10 `/ai/class-analysis`；Java 侧先聚合本班 `student_kp_mastery`、`wrong_question`、`interaction_record` 数据再送 AI，输出 `overview/weakTop10/errorSummary/advice`；只做教学分析，禁止答疑与出题；`report` 存 `reportType=CLASS_ANALYSIS`，内容存 JSON。
- **即时生效**：Java 不缓存配置，每次学生请求实时查询 `class_teacher_config`；配置与行为一致性由 `C-15/C-16` 用例验证（8.2-3 / 8.1-3）。

## 7. 全局约束的代码落点

| 约束 | 落点 |
| --- | --- |
| 知识库权威、不编造 | AI 检索为空 → 固定话术；`rules.py` 校验 |
| 教师配置最高优先级 | Java 每请求读配置；AI `/ai/qa` 入参带 config 并在提示词声明；后置校验 `blocked` |
| 学生侧引导式、不给答案 | 提示词硬规则 + `rules.py` 答案特征后置检查（命中则改写为引导语） |
| 交互写 `interaction_record` | Java 答疑/诊断/练习成功后统一落库 |
| mock/real 双模式 | `AI_MODE=auto/real/mock`；无 key 时 mock 也满足以上约束（固定话术、模板化讲解） |
| **v1.2** 答案不得暴露内部编号 | `service.py`/`rules.py` 后处理：`片段\s*\d+`、`chunk\s*\d+`、`kp\d{3}` 替换为 `citation` 或「知识库相关章节」；提示词中同样声明禁止 |
| **v1.2** 来源按片段去重 | `retrieval.py`/`service.py` 按 `chunkId` 去重（同检索单元保留最高分），前端显示「知识库来源（N 段）」 |
| **v1.2** 用户 Key 只用于本次请求 | Java 解密后经 `llm` 传入，AI 不写日志/不入库/不回显；接口只回掩码 |
| **v1.3** 图片只转文字、不解答 | 视觉提示词要求「原样输出题目/公式、不要解答」；识别结果回填前端可编辑，图片不落库不写日志；大小 5MB、类型 png/jpeg/webp/gif |
| **v1.3** gate 答案与通过线只在服务端 | 3 题正确答案存 AI 服务端 GateStore（v1.4.1 起 SQLite `ai-service/data/gate.db`，TTL 2h，重启不丢），响应只下发题干与选项；通过线 2/3；FAILED 不调用 LLM、不生成教学答案 |
| **v1.3** 硬拦截与 gate 互斥 | 先 `hard_scope_hit` 再 `teacher_scope_hit`；硬拦截不产生 gate；矩阵等仍逐字统一话术（保证 8.2-2 与 C-16b） |
| **v1.2** 多轮上下文可追溯 | `conversation` 表 + `interaction_record.conversation_id`；`/api/conversations/{id}` 返回该会话全部消息（含 sources/blocked） |

## 8. 与扣子版本的差异

| 维度 | 扣子 | 本项目 |
| --- | --- | --- |
| 工作流编排 | 画布节点 + IF 分支 | Java 服务编排 + AI 服务内部函数；意图由 AI3 返回、Java 路由 |
| 数据表 | 扣子数据表 | H2（10 张表 = PRD 7 核心 + `class_info`/`config_change_log`/`conversation` 3 辅助，JPA），教师配置读库不缓存 |
| 知识库 | 扣子知识库 | 本地 markdown KB1~KB5；v1.1 用 LangChain `InMemoryVectorStore` + 本地 n-gram 哈希 Embeddings（`knowledge.py`），`retrieval.py` 的 TF 检索保留作对照，无外部 embedding 服务 |
| Bot 入口 | 扣子 Bot | Vue 前端页面（学生 8 页 / 教师 6 页） |
| 图片答疑 | image_url 支持（扣子视觉节点） | **v1.3 已实现**：图片上传 → AI17 `/vision/extract` → 硅基流动 Qwen3-VL-8B 转文字 → 回填输入框后再走文字答疑；图片不落库、不进上下文 |
| 提示词维护 | 扣子 LLM 节点 | `ai-service/app/prompts.py` 模块常量，修改需改代码并重启，测试用 `/ai/qa` 直连 |

## 9. 提示词修改流程（防止改坏验收项）

1. 改 `ai-service/app/prompts.py`（或对应模块）中的模板；
2. 同步更新 `coze/01-提示词模板.md` 的副本；
3. 重启 AI 服务，用 `POST /ai/qa`（`{"message":"洛必达法则适用条件","config":{...},"mastery":[]}`）验证；重点回归 8.1-2（不给答案）与 8.2-2（拦截话术）；
4. 跑 `scripts/acceptance_check.py` C-07/C-08/C-16 及相关用例；
5. 在 `docs/开发过程/07-测试与验收记录.md` 记录变更与回归结果。

## 10. 已知差异与风险

- v1.1 改造已完成：LangChain 向量检索、`citation` 等引用字段与四类场景矩阵均已落地并实测，结果见 `docs/开发过程/07` §8 V-01~V-09（2026-11-07，real 模式 20/20 PASS）；
- 提示词集中 `ai-service/app/prompts.py`；若后续拆分文件，以 `ai-service/app/` 实际结构为准，本文档 §1 表给出逻辑对应；
- 真实 DeepSeek 与 mock 输出格式可能不同，Java 侧必须做字段容错（缺失 sources/weakPoints 用空数组兜底；`knowledgeCovered` 缺省按 true、`scopeWarning` 缺省按 null、`citation` 缺省回退 title+excerpt），不得因 AI 格式小差异导致 500；
- real 模式已是默认路径且已复测（2026-11-07 real 20/20，`/health` 返回 `mode=real`、`llm_ready=true`）：`/health` 的 `mode` 与 `llm_ready` 仍是最直接的判据，演示前先看一次健康检查。
- **v1.2 事实**：DeepSeek 无 embeddings 接口（实测 `POST /embeddings` 404），因此默认 `EMBEDDING_PROVIDER=local`；若写「接 DeepSeek embedding」即与事实不符，答辩时按契约 01 §10.1 表述为「本地向量 + 混合检索，可选 OpenAI 兼容 embedding」；
