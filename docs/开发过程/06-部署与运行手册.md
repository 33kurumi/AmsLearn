## 3. Java 业务服务（8080）

### 3.1 启动

双击 `scripts\启动Java服务.bat`（推荐）。脚本会：检测 java 版本（<17 直接报错）→ 由 java 路径推导 `JAVA_HOME` → 设置 `MAVEN_OPTS=-Dfile.encoding=UTF-8` → 检查 8080 占用 → `call mvnw.cmd spring-boot:run`。

手动启动：

```bat
cd business-service
mvnw.cmd spring-boot:run
```

健康检查：<http://localhost:8080/api/health>（返回 `{"success":true,...,"status":"UP"}`）；Actuator：<http://localhost:8080/actuator/health>。

首次启动会自动建表并写入演示数据（2 班/2 教师/5 学生/67 知识点及掌握度、记录、报告等），见 `DemoDataSeeder`。

### 3.2 构建与测试

```bat
cd business-service
mvnw.cmd -o -q -DskipTests package     :: 打包（含 Spring Boot repackage，生成可执行 jar）
mvnw.cmd -o test                       :: 单元测试（ApiIntegrationTest 13 个用例）
```

- **必须用 `package` 生成可执行 jar**：只执行 `mvn test` 时 `target/` 里的 jar 没有 `Main-Class`，`java -jar` 会报「没有主清单属性」；`package` 会触发 spring-boot-maven-plugin 的 repackage。
- 离线构建加 `-o`（要求本地仓库已有依赖）；首次跑 test 约 13~20 秒。
- 实测（2026-10-25）：`Tests run: 13, Failures: 0, Errors: 0, Skipped: 0`；AI 服务 `python -m unittest discover -s tests -v` 为 `Ran 31 tests ... OK`。

**Maven Wrapper 下载被拦截时**（DSH 沙箱/断网环境常见）：首次运行会尝试下载 Maven 3.9.9 到用户目录，若被拒绝，改用本机已安装的 Maven 3.9.x 完整路径，例如：

```bat
"C:\Users\<用户名>\.m2\wrapper\dists\apache-maven-3.9.12-bin\...\bin\mvn.cmd" -o spring-boot:run
```

学生双击 `启动Java服务.bat` 时走 Wrapper，一般不受沙箱限制；若课堂无网，请教师提前把 Maven 3.9.x 放到本机并改脚本最后一行为该路径。构建离线可加 `-o`（需本地仓库已缓存依赖）。

### 3.3 H2 数据库

- JDBC URL：`jdbc:h2:file:./data/student-project;AUTO_SERVER=TRUE`
- 用户名 `sa`，密码空；数据文件 `business-service/data/student-project.mv.db`
- 控制台：<http://localhost:8080/h2-console>（JDBC URL 填上面一行）
- `spring.jpa.hibernate.ddl-auto=update`：改实体后重启自动补列；**演示数据幂等**，重复启动不会重复插入
- 重置数据：运行 `scripts\重置H2数据.bat`（必须先停止 Java/AI 服务，确认后删除 H2 文件与 AI 索引状态，重启后自动重建）
- **沙箱下 H2 只读自愈（预期行为）**：若 H2 文件被新进程判定为只读，启动时会探测 `write_probe`，失败则把原库备份为 `student-project*.db.readonly.bak` 并重建库、重新导入演示数据。启动日志出现「检测到 H2 数据库文件为只读…已备份」属正常，无需处理；若想从干净演示数据开始，直接跑 `重置H2数据.bat`。

### 4.2 配置 DeepSeek key（mock/real）

复制模板并填写 key：

```bat
cd ai-service
copy .env.example .env
notepad .env
```

```ini
AI_MODE=auto
DEEPSEEK_API_KEY=sk-你的key
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
LLM_TIMEOUT_SECONDS=90

# v1.2（可选）：Embedding provider 与查询扩展
EMBEDDING_PROVIDER=local        # local（默认，本地哈希向量，无需额外 Key）| openai（OpenAI 兼容 embeddings 接口）
EMBEDDING_BASE_URL=             # provider=openai 时必填，如 https://api.openai.com/v1
EMBEDDING_API_KEY=              # provider=openai 时的 Key；缺省或失败自动回退 local
EMBEDDING_MODEL=                # provider=openai 时的模型名，如 text-embedding-3-small / BAAI/bge-m3（硅基流动）
EMBEDDING_MIN_SCORE=0.40        # 仅 provider=openai 生效：语义向量的「知识库是否覆盖」阈值
RETRIEVAL_MIN_SCORE=0.15        # 仅 provider=local 生效：本地哈希向量的「知识库是否覆盖」阈值
QUERY_EXPANSION=auto            # auto（默认，real 模式下用 DeepSeek 改写查询）| off

# v1.3（可选）：图片识别（硅基流动 OpenAI 兼容视觉模型）
VISION_PROVIDER=auto            # auto（有 key 即启用）| siliconflow | none
VISION_BASE_URL=https://api.siliconflow.cn/v1
VISION_API_KEY=                 # 留空则回退 EMBEDDING_API_KEY（同一硅基流动账号）
VISION_MODEL=Qwen/Qwen3-VL-8B-Instruct   # 可选 Qwen/Qwen3-VL-32B-Instruct
VISION_TIMEOUT_SECONDS=60

# v1.4.1（可选）：前置自测 gate 状态库（默认 data/gate.db，留空用默认）
AI_GATE_DB=
```

- **key 放哪里**：从 `ai-service/.env.example` 复制为 `ai-service/.env`，只在 `DEEPSEEK_API_KEY=` 后面填 `sk-...`；不要写进代码、不要提交、不要截图。
- **禁止提交**：`ai-service/.env` 已在项目 `.gitignore` 中（与 `frontend/.env`、`.venv` 同列），提交时报错或被包含请立即撤销；提交 `.env.example` 即可。
- `AI_MODE=auto`（默认）：**填了 key 即走真实 DeepSeek（默认路径，`/health` 显示 `mode=real`、`llm_ready=true`）；没填自动降级 mock**。无 key 也能完整演示与验收（2026-10-25 全量验收即 mock 模式 20/20 PASS）。
- `AI_MODE=mock` 强制模拟；`AI_MODE=real` 强制真实（无 key 启动会报错）。
- **改完 `.env` 必须重启 AI 服务**（uvicorn 只在启动读环境变量）；`/health` 的 `mode` 字段可确认当前模式（`mock`/`real`）。
- **模型名口径（v1.2）**：本地实测 `.env` 用 `deepseek-flash`（DeepSeek 当前可用模型为 `deepseek-flash`、`deepseek-v4-pro`）。代码缺省值已于 2026-11-07 统一为 `deepseek-flash`；**部署后一律以 `/health` 返回的 `model` 为准**。
- **Embedding 双轨（v1.2）**：DeepSeek **没有** embeddings 接口（实测 `POST https://api.deepseek.com/embeddings` 返回 404，`GET /models` 只有 chat 模型），因此默认 `EMBEDDING_PROVIDER=local`（本地哈希向量）+ 混合检索与查询扩展；需要语义向量时配 `EMBEDDING_PROVIDER=openai` 指向任意 OpenAI 兼容服务，**配错/超时自动回退 local，不影响答疑**。启动后看 `/health` 的 `embedding_provider`、`embedding_model`、`embedding_dim`。
- **检索阈值随 embedding 方案区分（2026-11-07 实测校准）**：`local`（本地哈希向量）对无关问题的分数接近 0，用 `RETRIEVAL_MIN_SCORE`（默认 **0.15**）；`openai`（bge-m3 等语义向量）对无关问题也会给到 **0.28~0.39**、相关问题 **0.70~0.99**，因此用 `EMBEDDING_MIN_SCORE`（默认 **0.40**），否则「今天天气怎么样」会被误判为「知识库已覆盖」。实现入口：`ai-service/app/config.py` 的 `settings.effective_min_score()`、`app/vector_store.py` 的 `VectorIndex.default_min_score()`；`/retrieve` 的 `minScore` 为**可选**参数，不传时用当前方案阈值，显式传值以请求为准。
- **图片识别（v1.3）**：**DeepSeek 不提供图像输入**，图片答疑改由 AI17 `/vision/extract` 转发到**硅基流动** OpenAI 兼容视觉接口（默认 `Qwen/Qwen3-VL-8B-Instruct`；2026-11-07 实测 AI 直连 **15.25s/张**，经 Java S18 代理端到端 **52.9s**（含上传与转发））。`VISION_API_KEY` 留空时自动复用 `EMBEDDING_API_KEY`（同一硅基流动账号），因此已配 bge-m3 的机器无需重复填；两者都没有则识图不可用（`/health` 的 `vision_ready=false`），前端「图片」按钮会提示改用文字输入。`VISION_PROVIDER=none` 可显式关闭。
- **图片隐私与限制（v1.3）**：单张 ≤5MB，仅 png/jpeg/webp/gif；前端会先压缩最长边 ≤1600px。图片**不落库、不写日志**，只在本机压缩后 base64 发往硅基流动做一次识别，识别出的文字回填输入框后可人工修改再发送；提交材料/截图中不得出现真实 key 与含个人信息的图片。
- **用户自带 Key（v1.2）不需要环境变量**：学生在「个人信息 → AI 模型设置」填入自己的 Key，Java 用 `app.crypto.secret`（AES/GCM）加密存 H2，只回掩码；答疑时解密后随请求传给 AI，**不写日志、不回显、不落 AI 服务**。成功后顶栏徽标显示 `real · 我的 Key`，`/api/chat` 返回 `modelSource=user`。若 `app.crypto.secret` 变更，旧密文无法解密，系统按未配置处理并回退系统 Key。
- 真实模式现状：v1.1 起为默认路径；接口已实现真实调用与超时/异常降级。**真实 key 的正式复测记录仍待在 `docs/开发过程/07` §8 回填**；答辩若现场用 real，提前 10 分钟验证 `/health` 的 `mode=real` 与一次答疑，并准备删除/置空 key 回退 mock。

### 4.3 启动

双击 `scripts\启动AI服务.bat`；或手动：

```bat
cd ai-service
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

健康检查：<http://localhost:8000/health>，返回示例（v1.1 基线；v1.2 追加下列字段，**实际以运行结果为准**）：

```json
{"status":"UP","mode":"real","knowledge_documents":5,"knowledge_chunks":60,
 "model":"deepseek-flash","llm_ready":true,
 "vector_store":"InMemoryVectorStore","embedding":"LocalHashingEmbeddings",
 "vector_dim":1024,"vector_count":276}
```

v1.2 新增字段（同一次 `/health` 返回中追加）：

```json
{"embedding_provider":"local","embedding_model":"LocalHashingEmbeddings",
 "embedding_dim":1024,"retrieval_mode":"hybrid","supports_user_key":true}
```

v1.3 新增字段（同一次 `/health` 返回中追加；2026-11-07 17:35 实测：`vision_provider=siliconflow`、`vision_model=Qwen/Qwen3-VL-8B-Instruct`、`vision_ready=true`，同时 `embedding_provider=openai`、`embedding_model=BAAI/bge-m3`、`vector_count=276`）：

```json
{"vision_provider":"siliconflow","vision_model":"Qwen/Qwen3-VL-8B-Instruct","vision_ready":true}
```

- `mode`：有 key 为 `real`，无 key 为 `mock`。
- `model`/`modelSource`：AI 服务当前模型；`modelSource` 为 `system`（系统 Key）或 `mock`。用户自带 Key 时该字段不在 `/health` 体现，而在 `/api/chat` 与 `/api/health` 的 `modelSource=user` 体现（契约 01 §10.8）。
- `retrieval_mode=hybrid`：v1.2 起检索为「向量 + 关键词」混合，配合查询归一化/同义扩展（`QUERY_EXPANSION=auto` 时 real 模式用 DeepSeek 改写查询）。
- `knowledge_chunks`（知识块数，实测 60）与 `vector_count`（检索单元数，v1.2 实测 **276**；v1.1 为 135）**不相等属预期**：先按章节切 60 个知识块，v1.2 起再按行首 `kpNNN` 对齐知识点后用 `RecursiveCharacterTextSplitter(420/60)` 切成 276 个检索单元入库；两者均 >0 即可，判定口径见 `docs/开发过程/07` §8 V-02 与 §9。
- `vision_provider`/`vision_model`/`vision_ready`（v1.3）：识图能力是否可用；未配 `VISION_API_KEY` 且无 `EMBEDDING_API_KEY` 时 `provider=none`、`ready=false`，AI17 返回 `ok=false`，前端提示改用文字输入。
- 接口文档：<http://localhost:8000/docs>（v1.3 新增 `POST /vision/extract`、`POST /qa/gate/check`）。

## 8. 三端验收脚本

```bat
:: 在项目根目录（含 README.md 的 AmsLearn 文件夹）内执行
.venv 不存在时先创建：cd ai-service && python -m venv .venv && cd ..
ai-service\.venv\Scripts\python.exe scripts\acceptance_check.py
```

参数：`--base-java`（默认 `http://localhost:8080`）、`--base-ai`（默认 `http://localhost:8000`）、`--base-web`（默认 `http://localhost:5173`）、`--skip-web`、`--timeout`、`--ai-timeout`、`--verbose`。

## 9. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| pip 安装长时间无输出（像卡死） | 默认缓存在用户目录被拒绝 | 按 §4.1 的 `--no-cache-dir` + `TMP` 方案重装 |
| npm install 报 `EPERM/EACCES` 或卡住 | npm 缓存目录不可写 | 设 `npm_config_cache` 到工作区后重试；必要时删除残留 `node_modules` 重装 |
| `mvnw.cmd` 首次运行卡在 Downloading | Wrapper 需下载 Maven 3.9.9，被网络/沙箱拦截 | 用本机已有 Maven 3.9.x 完整路径（§3.2），或教师提供离线 Maven |
| 8080/8000/5173 端口被占用 | 上次服务未关或端口冲突 | 运行 `停止全部服务.bat`；仍占用则用 `netstat -ano` 加 `findstr :8080` 查 PID 后结束 |
| 中文乱码（日志/控制台） | 代码页不是 UTF-8 | 脚本已 `chcp 65001`；手动启动先执行 `chcp 65001`，Java 已设 `-Dfile.encoding=UTF-8` |
| H2 文件删除失败/库被锁 | Java 进程仍占用 `.mv.db` | 先停 Java 服务再重置；`AUTO_SERVER=TRUE` 仅允许多连接，不允许删文件 |
| 改了 `.env` 但仍是 mock | 环境变量只在启动时读取，或 key 为空/占位值 | 重启 AI 服务；看 `/health` 的 `mode` 与 `llm_ready`；确认 `DEEPSEEK_API_KEY` 非空 |
| `/health` 没有 `vector_*` 字段 / `vector_count=0` | AI 服务是旧版本或索引尚未构建完成 | 拉取 v1.1 代码并重启；启动完成后访问 `/health`，必要时 `POST /ai/knowledge/rebuild` 重建索引 |
| 来源卡片只有文档名、没有 citation | 命中块缺章节元数据（`knowledge_points.json` 关联缺失）或前端为旧版本 | 确认知识点元数据有 `chapter`；AI 重建索引后重试；前端 v1.1 会回退显示 title+excerpt |
| 前端 401/一直跳登录 | token 过期或 Java 未启动 | 重新登录；确认 8080 已启动、`/api/health` 正常 |
| 公式显示为源码 | KaTeX 未渲染或未安装依赖 | `npm install` 后重启 dev；确认 `src/components/MarkdownView.vue` 正常 |
| AI 接口 503/超时 | AI 服务未启动或真实模型超时 | 检查 8000；真实模式超时会自动降级，Java 返回可读错误 |
| `java -jar` 报「没有主清单属性」 | 只跑了 `mvn test`，jar 未 repackage | 用 `mvn -o -q -DskipTests package` 重新打包（§3.2） |
| 启动日志「检测到 H2 数据库文件为只读…已备份」 | 沙箱导致库文件只读，自愈监听器重建了库 | 预期行为，无需处理；数据会重新导入演示数据（§3.3） |
| 教师最大难度调低后某层练习无题 | 历史问题：难度上限低于 C 层下限时按层筛选为空 | 已修复（mock 出题改为「难度上限优先」回退，返回 ≤上限的最接近题目），确认 AI 服务已重启 |
| 配了 `EMBEDDING_PROVIDER=openai` 后答疑报错/很慢 | 服务地址或 Key 不可用 | 会自动回退 local（看 `/health` 的 `embedding_provider`）；确认 `EMBEDDING_BASE_URL` 以 http(s) 开头、模型名存在 |
| 想接 DeepSeek 官方 embedding | DeepSeek 无 embeddings 接口（实测 404） | 属平台限制，不是本系统 bug：保持 `EMBEDDING_PROVIDER=local`，或换任意 OpenAI 兼容 embedding 服务（§4.2） |
| 换成 bge-m3 等语义 embedding 后，闲聊「今天天气怎么样」被判为知识库已覆盖 | 语义向量分数基线高（无关问题 0.28~0.39），`local` 的 0.15 阈值对 `openai` 过低 | 已按方案区分阈值：`openai` 用 `EMBEDDING_MIN_SCORE`（默认 0.40），`local` 用 `RETRIEVAL_MIN_SCORE`（0.15）；仍误判可在 `.env` 调到 0.45~0.55 后**重启 AI 服务**（§4.2、§9） |
| 填了自己的 Key 但徽标还是「系统 Key」 | 未开启「使用我的 Key」/保存未生效/Key 失效 | 个人信息 → AI 模型设置，确认开关打开并保存；看 `/api/profile/ai` 的 `enabled` 与 `hasApiKey`；Key 错误时自动回退系统 Key 再回退 mock |
| 重启后自己的 Key 失效（提示解密失败/变回系统 Key） | `app.crypto.secret` 被改动，旧密文无法解密 | 用同一 `app.crypto.secret` 重启；或重新在页面保存一次 Key |
| 答疑页历史会话为空/不能继续对话 | 前端是旧版本，或该记录的 `conversationId` 为空（v1.2 之前的旧数据） | 用 v1.2 前端；旧记录没有会话归属属预期，重新提问会新建会话 |
| 回答里出现「片段 5」「kp012」 | AI 服务是旧版本（未做内部编号清理） | 拉取 v1.2 代码重启；答案应引用 `citation`（如「第4章·第4节 分部积分法」） |
| 页面数据为空 | 未初始化/数据库被重置未重启 | 重启 Java 服务触发种子数据；必要时 `重置H2数据.bat` 后重启 |
| 点「图片」提示「未配置识图模型…」 | 既没有 `VISION_API_KEY`，也没有可复用的 `EMBEDDING_API_KEY` | 在 `ai-service/.env` 填任一个 key 后**重启 AI 服务**；或仍用文字输入（不影响验收） |
| 上传图片提示「图片识别失败，请重试或改为文字输入。」 | 视觉模型超时/网络不可达/图片模糊无法识别 | 确认 `VISION_BASE_URL` 可访问、换清晰图片；重试仍失败改文字输入，图片链路属增强项，不影响 8.1/8.2 主验收 |
| 问教师禁用知识点（如级数）不再返回拦截话术，而是一张「前置自测 · 共 3 题」卡片 | **v1.3 语义变化（已实测）**：教师配置的暂缓/超纲内容改为前置自测后教学；硬拦截只剩课程外数学（矩阵/线代/概率/物理/复变/数分/离散）与不当请求 | 属新设计；答完 3 题 ≥2 题正确即进入三步教学（实测 2/3 通过、15.62s、教学 3 步 + 来源 4 条）。想回到硬拦截请改回 v1.2 代码（不推荐） |
| 提交前置自测后提示「前置测试已过期」 | **v1.4.1 起只有一种原因：gate 创建已超过 TTL（2 小时）**；已改为 SQLite 持久化（`ai-service/data/gate.db`），服务重启不再丢 | 在答疑页重新提问该知识点，会生成新的 gate；想彻底重置所有 gate 状态就停 AI 后删除 `data/gate.db` 再启动 |
| 重启 AI 后正在做的前置自测还能继续答吗 | v1.4.1 已持久化（未过期即可续答，已通过主题不再重复出题）；若看到 gate 丢失，多为库目录不可写触发**内存回退**（日志有「回退内存模式」）或库被删 | 检查 `ai-service/data/` 可写、`AI_GATE_DB` 路径正确；正常情况下重启后同会话同主题直接进入正常答疑 |
| 图片识别成功但答案没有参考图片内容 | 设计如此：图片只转文字，**不回写多轮上下文、不落库**；答案依据回填后的文字 | 确认回填文字是题目（可手动修改）再发送；需要上下文时把关键条件补进文字 |
