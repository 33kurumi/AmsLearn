# 05 数据模型与初始化数据

> 对应契约：`docs/开发过程/01-接口约定.md`（实施基线 v1.0；**v1.2 增补见其 §10**）。
> 数据访问方式：Spring Data JPA，`spring.jpa.hibernate.ddl-auto=update` 自动建表/补列；数据库文件 `business-service/data/student-project.mv.db`。

## 1. 总览

PRD 要求 7 张核心表，本系统在同一 H2 库中落地 7 张核心表 + 3 张支撑表（`class_info` 班级主数据、`config_change_log` 配置留痕、`conversation` 多轮会话），**实库共 10 张表**（`domain` 下 10 个 `@Entity`、`repository` 下 10 个 Repository 一一对应）：

| # | 表名 | 唯一标识 | 职责 | 对应 PRD 实体 |
|---|------|---------|------|--------------|
| 1 | `user_info` | `id`（`username` 唯一） | 学生/教师账号、班级归属、密码散列 | 用户信息 user_id |
| 2 | `class_teacher_config` | `id`（`class_id` 唯一） | 班级教学配置（回答模式/难度上限/范围/边界/知识库权限/禁用话题） | 班级教师配置 config_id |
| 3 | `knowledge_point` | `kp_id` | 67 个高数知识点目录（章节、难度、学时、目标、要点） | 知识点目录 kp_id |
| 4 | `student_kp_mastery` | `id`（`student_id,kp_id` 联合唯一） | 学生对每个知识点的掌握度、答题次数、正确次数 | 学生知识点掌握 |
| 5 | `interaction_record` | `id` | 答疑/诊断/练习/计划全部交互留痕 | 交互答题记录 record_id |
| 6 | `wrong_question` | `id` | 错题本（诊断、练习、答疑产生的错题） | 错题记录 error_id |
| 7 | `report` | `id` | 诊断报告、学习计划、练习批次、班级分析报告 | 学习与分析报告 report_id |
| 8 | `class_info`（辅助） | `class_id` | 班级主数据（class_id / class_name / subject），v1.2 注册校验默认班级存在、班级列表接口从此表读 | 非 PRD 7 表对象 |
| 9 | `config_change_log`（辅助） | `id` | 班级配置修改留痕，支撑 T4 接口 | PRD「配置修改留痕」 |
| 10 | `conversation`（v1.2 辅助） | `id` | 学生答疑会话（标题、消息数、时间），支撑多轮上下文与「继续对话」 | 非 PRD 7 表对象；`interaction_record.conversation_id` 关联 |

设计取舍：
- **诊断会话复用 report 表**：`POST /api/diagnose/start` 先创建 `report(type=DIAGNOSIS,status=IN_PROGRESS)`，`sessionId=reportId`；提交后更新为 `COMPLETED` 并写入成绩与逐题结果。避免额外会话表，契约的 `sessionId=reportId` 即由此而来。
- **练习批次复用 report 表**：`report(type=PRACTICE)` 的 `content` 存 `{batchId,layer,kpIds,questions,guidance}`，`batchId` 取 `"PB"+report.id`，供 `S13 /practice/hint` 反查题目。
- **计划复用 report 表**：`report(type=PLAN)` 的 `content` 存完整 `PlanVO`（含 `days[]`），每日 `done` 状态回写该 JSON。
- **班级分析复用 report 表**：`report(type=CLASS_ANALYSIS,teacher_id=当前教师)`，`content` 存 T6 结构。
- 班级主数据落 `class_info` 表（`class_id` 为主键，`C-GS-01`/`C-GS-02` 由种子数据写入），v1.2 起注册需校验 `app.default-class-id` 在该表存在、教师端班级列表也从此表读；`user_info.class_id` 仅存字符串编码，全仓不用 `@ManyToOne` 外键约束。
- **v1.2 会话表**：`CONVERSATION` 只存会话元信息（标题/消息数/时间），消息本身仍在 `interaction_record`（加可空 `conversation_id`），不重复存内容；旧记录的 `conversation_id` 为 NULL，前端按「单条问答」展示。

## 2. 表结构

字段类型以 H2 为准；`CLOB` 用于长文本/JSON，`VARCHAR` 用于可索引短字段。时间统一 `TIMESTAMP`，接口输出 ISO-8601 本地时间字符串（`Asia/Shanghai`）。

### 2.1 user_info

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 用户 ID，接口中的 `userId`/`studentId`/`teacherId` |
| username | VARCHAR(50) | NOT NULL, UNIQUE | 登录名：teacher1/teacher2/student1~student5 |
| password_hash | VARCHAR(200) | NOT NULL | PBKDF2 加盐散列（格式 `pbkdf2$迭代次数$salt$hash`），禁止明文 |
| display_name | VARCHAR(50) | NOT NULL | 展示名：王老师/张同学等 |
| role | VARCHAR(20) | NOT NULL | `STUDENT` / `TEACHER` |
| class_id | VARCHAR(30) | 可空 | 学生与教师均归属班级：C-GS-01 / C-GS-02 |
| email | VARCHAR(100) | 可空 | 邮箱（A5 可改），演示数据预置 studentN@example.com |
| phone | VARCHAR(30) | 可空 | 手机号（A5 可改），演示数据预置 1380000000N |
| target_school | VARCHAR(100) | 可空 | 目标院校（A5 可改），如 华东理工大学 |
| exam_year | INT | 可空 | 考研年份，如 2027 |
| created_at | TIMESTAMP | NOT NULL | 创建时间 |
| ai_api_key_enc | VARCHAR(512) | 可空 | **v1.2**：用户自带 DeepSeek Key 的 AES/GCM 密文（Base64），只存密文；接口只回掩码 |
| ai_base_url | VARCHAR(200) | 可空 | **v1.2**：用户自定义 Base URL（必须 https 开头，默认 `https://api.deepseek.com`） |
| ai_model | VARCHAR(100) | 可空 | **v1.2**：用户选择的模型（`deepseek-flash`/`deepseek-v4-pro`/自定义） |
| ai_enabled | BOOLEAN | NOT NULL, 默认 false | **v1.2**：是否「使用我的 Key」 |

> 头像 `avatar` 不在表内：前端无图时用姓名首字生成色块即可。
> `lastActiveAt` 由 `interaction_record` 最近时间派生（T7 输出），不单独落列，避免双写不一致。

索引：`uk_user_info_username(username)`；`idx_user_info_class_role(class_id, role)`。

> v1.2 说明：四个 `ai_*` 列由 `ddl-auto=update` 自动补列，旧库无需手工迁移；`app.crypto.secret` 必须固定，否则重启后旧密文无法解密（此时按未配置处理、回退系统 Key）。演示数据不预置用户 Key。

演示数据中的个人信息（与 DemoDataSeeder / 契约 A1/A5 一致）：student1 张同学（华东理工大学 / 2027 / 13800000001）、student2 李同学（上海大学 / 2027 / 13800000002）、student3 王同学（同济大学 / 2027 / 13800000003）、student4 赵同学（东华大学 / 2028 / 13800000004）、student5 陈同学（上海理工大学 / 2028 / 13800000005），邮箱均为 studentN@example.com；teacher1 王老师（teacher1@example.com / 13900000001）、teacher2 李老师（teacher2@example.com / 13900000002）。

### 2.2 class_teacher_config

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 配置 ID |
| class_id | VARCHAR(30) | NOT NULL, UNIQUE | 班级编码 |
| class_name | VARCHAR(100) | NOT NULL | 考研高数强化班 / 考研高数基础班 |
| subject | VARCHAR(50) | NOT NULL | 固定「高等数学」 |
| teacher_id | BIGINT | NOT NULL | 归属教师 |
| answer_mode | VARCHAR(20) | NOT NULL | `GUIDED`/`DIRECT`/`MIXED`，默认 `GUIDED` |
| max_difficulty | INT | NOT NULL | 1~4，默认 2；出题/诊断不得高于该值 |
| scope_mode | VARCHAR(20) | NOT NULL | `ALL`/`CHAPTER`/`CUSTOM`，默认 `ALL` |
| scope_chapters | CLOB | 可空 | JSON 数组，如 `["函数极限连续","导数微分"]` |
| scope_kp_ids | CLOB | 可空 | JSON 数组，如 `["kp001","kp015"]`；`ALL` 时为空 |
| boundary_rules | CLOB | 可空 | 自由文本，≤500 字，超长 400 |
| kb1_enabled | BOOLEAN | NOT NULL | KB-1 课程大纲，默认 true |
| kb2_enabled | BOOLEAN | NOT NULL | KB-2 教材讲义，默认 true |
| kb3_enabled | BOOLEAN | NOT NULL | KB-3 题库解析，默认 true |
| kb4_enabled | BOOLEAN | NOT NULL | KB-4 教师授权资料，默认 false |
| disabled_topics | CLOB | 可空 | JSON 数组，命中即拦截，如 `["级数","微分方程"]` |
| updated_at | TIMESTAMP | NOT NULL | 最近修改时间 |
| updated_by | BIGINT | 可空 | 最近修改教师 |

约束：`answer_mode IN ('GUIDED','DIRECT','MIXED')`、`max_difficulty BETWEEN 1 AND 4`、`scope_mode IN ('ALL','CHAPTER','CUSTOM')`（JPA 层用枚举 + `@Min/@Max` 校验，非法返回 400 `VALIDATION_ERROR`）。
索引：`uk_class_config_class_id(class_id)`、`idx_class_config_teacher(teacher_id)`。

派生规则（Java 在调用 AI 前计算）：
- `effectiveKpIds`：`ALL` → 空数组（表示全部 67 个）；`CHAPTER` → 该章节下 kpId 集合；`CUSTOM` → `scope_kp_ids`。
- 修改配置后**对后续请求立即生效**：每次请求实时读库，不做进程内缓存；并写 `config_change_log`。

### 2.4 student_kp_mastery

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | BIGINT | PK, 自增 | 主键 |
| student_id | BIGINT | NOT NULL | 学生用户 ID |
| kp_id | VARCHAR(10) | NOT NULL | 知识点 ID |
| mastery | DECIMAL(4,3) | NOT NULL, 默认 0 | 掌握度 0.000~1.000，保留 2 位展示 |
| attempts | INT | NOT NULL, 默认 0 | 累计作答次数 |
| correct_count | INT | NOT NULL, 默认 0 | 累计答对次数 |
| last_practiced_at | TIMESTAMP | 可空 | 最近练习时间 |
| updated_at | TIMESTAMP | NOT NULL | 最近更新时间 |

约束：`UNIQUE(student_id,kp_id)`；索引 `idx_mastery_student(student_id)`、`idx_mastery_kp(kp_id)`。

状态派生（不落库，接口实时计算，与契约一致）：

| 条件 | `status` | 前端颜色建议 |
|------|-----------|--------------|
| `attempts = 0` | 未开始 | 灰 |
| `mastery < 0.3` 且 `attempts > 0` | 薄弱 | 红 |
| `0.3 ≤ mastery < 0.7` | 一般 | 橙 |
| `mastery ≥ 0.7` | 良好 | 绿 |

注意：演示数据为每个学生预置 67 行（`attempts=0` 的行即「未开始」），保证 S1 的 `mastery.totalKp=67`、S2 返回 67 个知识点。

## 3. report.content 结构

### 3.1 DIAGNOSIS（`status=COMPLETED` 后）

```json
{
  "mode": "QUICK",
  "total": 5,
  "correctCount": 3,
  "score": 72,
```

## 5. 掌握度更新规则

1. 每次判分答对：`mastery = min(1.0, mastery + 0.05)`；答错：`mastery = max(0.0, mastery - 0.10)`。
2. `attempts += 1`；答对时 `correct_count += 1`；更新 `last_practiced_at`、`updated_at`。
3. 掌握度保留 3 位小数存储、2 位小数展示；四舍五入到百分位后再夹取边界，避免出现 0.999 显示 1.00 的分歧。
4. 诊断提交必须按「逐题结果」批量更新，事务内完成；S11 返回的 `masteryChanges[{kpId,kpName,before,after}]` 必须是更新前后值。
5. 边界情况：同一诊断中同一知识点多题，逐题累加后再返回该知识点最终 before/after（before 指本批次开始前值）。
6. 练习判分若当前版本不自动判分（只给提示/思路），则练习不更新掌握度；错题仍需在能判定对错时写入。**当前实现口径**：练习接口只生成题目与提示，掌握度更新发生在诊断提交；此取舍已写入 docs/开发过程/04 里程碑 M4 备注。
